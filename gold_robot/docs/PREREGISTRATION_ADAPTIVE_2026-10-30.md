# Preregistration — Adaptive Router Hardening, SMC Style 8, M1 Scalp
Date: 2026-10-30. Branch: independent/adaptive-robot-20261030. Base: main 6c8f786 + fix branch 5fc0929 incorporated.
Status: FROZEN. This document is written BEFORE any PnL evaluation of the hardened router, of Style 8, or of the M1 scalp path. Any change to a threshold, priority, score weight, or entry rule below, made after seeing returns, invalidates the run and restarts the clock on a fresh unseen window. No tuning on Jan–Feb 2026, no tuning on any window used to judge Styles 0–7, and no tuning on the validation window itself.

## Frozen hypotheses (all Tester-only, like Styles 4–7)
- H-R (router hardening): adding regime persistence (3 closed bars), transition abstention (priority 4 only, R>=1.0), and an ATR 90th-percentile volatility abstention does not create an edge by itself; it only reduces regime-flip churn. It is judged by the router's own safety_on results, not by cherry-picked regime slices.
- H-SMC (Style 8): a genuine FVG + order-block mitigation entry with BOS/CHoCH confirmation has a distinct signal from Styles 0–7 (see Style 8 section). It is unvalidated until it passes the gates below on unseen data.
- H-SCALP (M1, only if H-R and H-SMC are complete and tested): a closed-bar M1 scalp with bps TP/loss and a short time cap is spread/slippage-sensitive by construction; a positive close-bar result without real-tick broker costs is not a pass.

## Frozen parameters (not EA inputs, deliberately not optimisable)
Router hardening: ROUTER_PERSISTENCE_BARS=3; ROUTER_TRANSITION_MIN_PRIORITY=4; transition R>=1.0; ROUTER_ATR_LOOKBACK_BARS=50; ROUTER_ATR_ABSTAIN_PERCENTILE=0.90.
SMC Style 8 (see code): pivot lookback 5 closed bars each side for a swing pivot; displacement = close beyond swing by >0.10xATR; FVG = 3-bar gap (low of bar i+2 > high of bar i for longs, mirrored for shorts); order block = last opposing candle before the displacement bar; mitigation = closed-bar close back into OB/FVG zone; confirmation = a subsequent closed-bar close beyond the swing (BOS/CHoCH) in trade direction; entry = limit at the OB/FVG edge nearest price, SL = beyond the OB/FVG extreme + buffer (same buffer rule as existing Prepare*Limit: max(0.20xATR, 3xspread, stops-level+2 ticks) via the shared pipeline), TP = R x risk with RewardToRisk input, uncapped except broker spacing; expiry 2 bars, max hold 180 min (shared pipeline). No other SMC parameter exists in this preregistration; adding one (e.g. FVG size filter, OB width filter) is a new trial and restarts the clock.
M1 scalp (Style 9, implemented 2026-10-30 — numbers frozen here BEFORE any scalp PnL evaluation; no scalp return has been viewed at this point): timeframe M1 only (OnInit refuses any other timeframe for Style 9); signal = closed-bar efficiency/trend-pullback/range-fade/breakout logic ported from scalp_regimes.py propose_scalp_entry only (NOT the anticipatory/pre-breakout challenger) with its frozen thresholds (34 closed bars, past = bars 1..32, efficiency 0.43/0.28, pullback depth >= volatility, range quartile 0.25, breakout +0.2xvolatility past the last-20 extreme); entry = future LIMIT at the last closed M1 close; exit = broker SL/TP at frozen SCALP_TP_BPS=15.0 and SCALP_SL_BPS=12.0 (never widened to meet a broker gap — a violating stop fails the order), spread cap = the shared EA gate MaxSpreadBps (default 3 bps) in FreshEntryQuote, pending expiry = PendingExpiryBars (default 2 M1 bars), position time cap = MaxPositionMinutes which OnInit requires to equal exactly 15 for Style 9; no other scalp parameter. The auto-runner/presets cover styles 0–8 on M15 only; Style 9 requires the manual M1 run documented in the Windows instructions (EntryStyle=9, Period=M1, MaxPositionMinutes=15, safety_on).

## Validation window, presets, costs — to be filled BEFORE the run, never after
- Symbol/timeframe/model/deposit: XAUUSD@, M15 for router/SMC, M1 for scalp, Strategy Tester model 4 (every tick based on real ticks), $3,000, 1:100, WMMarkets, safety_on presets ONLY (TesterIgnoreDailyAndPeakStops=false, RiskPerTradePct=0.50). Census presets are discovery only and may never support a claim.
- Window: a fresh, previously unseen period AFTER 2026-10-30, chosen and dated in the evaluation report before running; it must not overlap Jan–Feb 2026 or any period already used to judge Styles 0–7. At least 100 closed trades per candidate, >=40 active days, >=20 trade days, >=3 months (edge_gate minima) are required before any positive screen.
- Costs: broker-measured only for a claim. Until a WMMarkets statement exists, costs are ASSUMED: $10/lot round-turn, $0.10 stop slippage, spread from tester ticks. Every result must be labelled ASSUMED, and a result with ASSUMED costs can at most be RESEARCH_POSITIVE_NOT_VALIDATED, never validated.
- Trial count: count EVERY variant, including router hardening (1), SMC (1), scalp (1), and every threshold/score-weight perturbation run in robustness. The main-branch edge_gate (BOOTSTRAPS=2000) resolves only <=4 trials; this branch's edge_gate (20000 bootstraps, cap 40) resolves up to 40. Declare the count honestly; if it exceeds the cap, report edge_gate lower=None as fail-closed and use DSR/Holm over the ledger-counted trial list.

## Gates (all must pass for a candidate; otherwise NO-GO for that candidate)
- edge_gate: net>0, stressed net>0, PF>1.15, multiplicity-adjusted 99% bootstrap lower>0 (or, if trial cap exceeded, DSR>=0.95 and Holm-adjusted p<0.05 with the cap limitation stated).
- Edgelab: alpha_t>=2.5 (DEV), DSR>=0.95, alpha_ann_stress>0 at 2x costs; validation alpha_t>0 and alpha_ann>0.
- Walk-forward: >=5 chronological folds, mean WFE>=0.30, mean OOS Sharpe>=0.30.
- Placebo: router/scalp/SMC must beat BOTH the best static style alone AND a placebo (shuffled regime labels / random router) on the same window; otherwise selection skill is unproven.
- Robustness: positive at 2x costs, 1.5x and 2x spread, and slippage stress; threshold perturbations counted as trials must not be the only passing configuration.
- Per-regime audit: trades broken by decision-time regime only (never ex-post); a total edge carried by a single failing regime slice is not a pass.
- Native evidence: unmodified, style-verified native MT5 HTML reports + forensic CSV, equity (not closed-only) drawdown, losing streak, fill/expiry/rejection counts, outlier sensitivity (median and ex-top-2-winners). Missing ledger = EVIDENCE_GAPS_NO_GO. Agent logs are never HTML reports.
- DEMO-forward: required after the tester-only block is changed and re-frozen; slippage, fill rate, and gap-stop behaviour must be consistent with the tester.

## Kill criteria
Any of: <100 closed trades, PF<=1.15, bootstrap lower<=0, DSR<0.95, alpha_t<2.5, stressed net<=0, WFE<0.30, OOS Sharpe<0.30, router <= best static or <= placebo, edge only at exact frozen thresholds, edge only at ASSUMED costs that disappears at 2x costs, DEMO divergence, or missing forensic ledger. A killed candidate is reported as killed with its failing gate named; it is not retuned on the same window.

## What this preregistration does NOT do
It does not claim any edge, any profitability, or any live readiness. Live trading stays disabled. The MQL5 code in this branch is UNCOMPILED on Linux (no MetaEditor/MT5) until Windows MetaEditor passes, and Python results are SCREENING ONLY — Python simulators cannot faithfully replicate the MQL5 router (different timeframe/indicators/regime/TP/sizing/fill/costs/session, per the quant audit), and local data has no data/raw/ with unconfirmed timestamp/price basis.
